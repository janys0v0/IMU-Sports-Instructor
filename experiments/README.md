shared code lives in `common/`. The running record of what was done, why, and what came out is
the project-level log: [`../EXPERIMENT_LOG.md`](../EXPERIMENT_LOG.md).

## Conventions

- **One folder per experiment**, named `ENN_short_name`. Its `README.md` states the question,
  method, how to run it and a results summary. `run.py` is the main entry point; any extra
  scripts (e.g. E02's `make_videos.py`) only read what `run.py` saved.
- **Results go in `ENN_.../results/<session id>/`** and are fully regenerated by `run.py`.
  Every run writes `metrics.json` (machine-readable) and `summary.md` (tables).
- **Shared code is model-agnostic.** A model runner returns `common.mobileposer_runner.Output`
  (time, SMPL local and global rotations, joints, translation); `common.metrics.score` works on
  any such output, so new models plug in without touching the metrics.
- **Same inputs for every model.** `common.session.load_session` does the calibration once, the
  same way the live viewer does; experiments only choose which devices a model sees.
- **Annotations are data, not code.** Activity windows and reported repetitions live in
  `annotations/<session>.json`; metrics use them when present.
- **Log every run** in `../EXPERIMENT_LOG.md`: date, experiment, session, command, headline
  numbers, and what changed.

## Running

From the repo root:

```bash
.venv/bin/python -m experiments.E01_mobileposer_device_ablation.run
.venv/bin/python -m experiments.E02_imucoco_comparison.run
.venv/bin/python -m experiments.E03_stream_quality.run
```

Terms: **data consistency** = quality of a sensor stream (rate, missing samples, gaps, delay;
E03). **Agreement** = how closely a model's bone follows the sensor on it (E01, E02).

All default to the reference session `20261008-153213-P01`; pass another session id to run on
it (activity metrics need an annotation file for that session).

## References without ground truth

There is no optical motion capture, so metrics use two references:

1. **Sensor-observed bones.** Each calibrated device measures the bone it is on (right forearm,
   right thigh, head). The model's global rotation of that joint is compared with it, whether or
   not the model was given that device. Caveat: a model that copies its input closely scores
   well here even if the calibration convention is off; a model that leans on its body prior
   scores worse but may be anatomically more plausible. Read it together with the activity metrics.
2. **Annotated activities.** Repetitions (peaks in wrist height / knee flexion), squat depth, and
   head yaw against the AirPods.
